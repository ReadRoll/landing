# Internationalization (i18n)

## 1. Goal

Serve readroll.xyz in **English** (default) and **French** without duplicating any layout or UI.

- **Landing page**: one template, with content that depends on the language.
- **Legal pages** (legal notice, privacy policy, terms of use): one document per language, all sharing one layout.
- **Visitors** are offered their browser's language once. After that, their choice is remembered and applied automatically.
- **Adding a language** must stay simple:
  - a config entry
  - a dictionary
  - translated legal Markdown files
  - an nginx `location` block

## 2. Implementation

### Routing

Uses Astro's built-in i18n routing, configured in `astro.config.mjs`:

```js
i18n: {
    defaultLocale: "en",
    locales: ["en", "fr"],
    routing: { prefixDefaultLocale: false },
}
```

- English pages have no prefix (`/`); French pages are prefixed (`/fr/...`).
- Get the page's language with `Astro.currentLocale`.
- Build URLs with `getRelativeLocaleUrl`.

### Translations

- Text comes from typed dictionaries:
  - `src/i18n/en.ts` is the source of truth.
  - `src/i18n/fr.ts` is typed as `typeof en`, so a missing key fails the build.
  - Keys are nested by section (`hero.title`, `features.items`, ...).
- The `useTranslations(locale)` helper returns the dictionary for a language.
- No i18n library (i18next, Paraglide):
  - The site is static and renders at build time, so it doesn't need a translation runtime.
  - Switch to Paraglide if we ever need plurals or ICU formatting, a translation platform, or many client-side islands that need strings.

### Pages

**Landing page**

- One `Home` component holds the layout and UI.
- `src/pages/index.astro` and `src/pages/fr/index.astro` are thin wrappers that render it.

**Legal pages**

Stored as Markdown in a `legal` content collection: `src/content/legal/{en,fr}/*.md`.

| key            | en              | fr                           |
| -------------- | --------------- | ---------------------------- |
| `legal-notice` | `/legal-notice` | `/fr/mentions-legales`       |
| `privacy`      | `/privacy`      | `/fr/confidentialite`        |
| `terms`        | `/terms`        | `/fr/conditions-utilisation` |

- Frontmatter fields:
  - `key` is shared between translations and links them.
  - `slug` is the URL segment, in the file's own language.
  - `title` and `description` are used for meta tags.
  - `updatedAt` is the last-update date.
- One shared legal layout:
  - It uses the same navbar as the home page and a narrow reading column.
  - "Last updated" / "Dernière mise à jour" is formatted per language with `Intl.DateTimeFormat`.

**404**

- `src/pages/404.astro` (en) and `src/pages/fr/404.astro` (fr) are rendered from one shared template.
- nginx (`docker/nginx.conf`) sends missing `/fr/...` URLs to the French page, with a real 404 status:

```nginx
location /fr/ {
    try_files $uri $uri/ $uri.html =404;
    error_page 404 /fr/404.html;
}
```

**Alternates map**

This map is the single source of truth for language links.

- Every page passes an `alternates` map to `Layout`, for example `{ en: "/privacy", fr: "/fr/confidentialite" }`.
  - On the landing page it is `{ en: "/", fr: "/fr" }`.
  - On legal pages it is built from the shared `key`.
- `Layout` uses this map for:
  - `<html lang>`
  - canonical and `hreflang` links
  - the navbar language switcher
  - the language banner
  - the redirect script

### Meta

- Translated `<title>` and `description`:
  - from the dictionary on the landing page
  - from frontmatter on legal pages
- `<html lang>`
- `<link rel="canonical">` pointing to the page itself
- `<link rel="alternate" hreflang>` for `en`, `fr`, and `x-default` → `en`
- `og:title`, `og:description`, `og:locale` (`en_US` / `fr_FR`)

## 3. Language banner

### Suggestion (first visit)

- Shown only when:
  - nothing is stored in `localStorage` yet, and
  - the first supported entry in `navigator.languages` differs from the page's language.
  - Example: a browser set to `de, fr` counts as `fr`; a browser set to `de` only gets no banner.
- Fixed position and dismissible, so it doesn't block the page or shift the layout.
- Written in the **suggested** language, e.g. _"Ce site est disponible en français. [Voir en français] [×]"_.
- Links to the matching page, not the home page.

### Saving the preference

Every choice is saved to `localStorage` **before** navigating. Saving after navigating would trap the visitor in a redirect loop.

| Action                    | Saves              |
| ------------------------- | ------------------ |
| Navbar language switcher  | target language    |
| Banner "Voir en français" | suggested language |
| Banner "×" (dismiss)      | current language   |

### Automatic redirect (later visits, all pages)

- A blocking `<script is:inline>` at the top of `<head>`, before CSS and fonts.
- If the stored language differs from the page's language, it calls `location.replace(alternates[stored])`.
  - Nothing has been painted yet, so there's no flash.
  - Using `replace` keeps the Back button from looping into the redirect.
- Skipped on 404 pages.
- Accepted trade-off: a visitor with `fr` stored who opens a shared English link lands on the French version. Crawlers start with empty storage, so they are not affected.
- If a Content-Security-Policy header is added to nginx later, this script will need its hash added to `script-src`.
