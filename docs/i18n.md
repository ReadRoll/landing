# Internationalization (i18n)

## Goal

Serve readroll.xyz in **English** (default) and **French** without duplicating any layout or UI. Adding a language must stay simple: a locale entry, a dictionary, page files, route map entries, translated content, an OG image and an nginx block.

## Routing

- Astro's built-in i18n routing: English has no prefix (`/`), other languages are prefixed (`/fr/`). Slugs are translated and written in kebab-case (`/legal` ↔ `/fr/mentions-legales`).
- The list of locales is declared once and shared by the Astro config and the translation code.
- A middleware resolves the current language once per request and exposes it, with its dictionary and its page URLs, to every component. Components never resolve the language themselves.
- Astro routes by file only: it has no named routes and does not type URLs. Every page's URL in every language is declared once in a hand-written route map, the single source of truth for internal links, `hreflang` tags and the language menu. A missing language or an unknown page is a type error.
- MDX content links to pages with route keys (`route:privacy`); a shared link component resolves them for the current language, and an unknown key fails the build.

See the Pages doc for how to add a page.

## Translations

- One JSON dictionary per language; English is the source of truth. Dictionaries are typed from English, so a missing key is a type error.
- Values that don't depend on the language, such as the contact email, stay out of the dictionaries and are inserted through placeholders.
- Long-form content is written once per language: legal pages as MDX files, changelog entries as Markdown files in one folder per language.
- No i18n library: the site is static and renders at build time. Switch to Paraglide if we need plurals, ICU formatting or a translation platform.

## Meta

- Pages provide their title, description and route key; a shared head component derives everything else (OG tags, `hreflang`).
- `hreflang` links come from the page's route map entry, plus `x-default` pointing to the default language. Pages without translations (404) get no links.
- The document title gets the site name appended (`Legal notice | ReadRoll`), except on pages whose title already contains it (landing). `og:title` stays without it, since `og:site_name` carries it.
- The description depends on the page; pages without one (404) get no description tag. The OG image depends on the language only.
- Pages that must stay out of search results (404) opt in to `noindex` explicitly. It isn't inferred from a missing route, so a future untranslated page isn't hidden by accident.
- No canonical and no `og:locale` for now.
