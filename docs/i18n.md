# Internationalization (i18n)

## Goal

Serve readroll.xyz in **English** (default) and **French** without duplicating any layout or UI.

- Visitors are offered their browser's language once; after that, their choice is remembered.
- Adding a language must stay simple: a locale entry, a dictionary, page wrappers, route map entries, an OG image, translated legal files, an nginx block.

## Key concepts

### Routing

- Astro's built-in i18n routing: English has no prefix (`/`), other languages are prefixed (`/fr/`).
- Astro does not generate pages: each language has its own thin page files that render shared components.
- The list of locales is declared once and shared by the Astro config and the translation code.
- Slugs are translated and written in kebab-case (`/legal` ↔ `/fr/mentions-legales`).

### Current language

- Resolved once per request by a middleware, from Astro's current locale, falling back to the default language.
- The middleware exposes the language and its dictionary to every component, so components never resolve the language themselves.
- Helpers take an already resolved language, never a raw or missing value.

### Route map

- Astro routes by file only: it has no named routes and does not type URLs.
- Every page's URL in every language is declared once in a shared route map, written by hand. It mirrors the page files; Astro does not check that they match.
- It is the single source of truth for language links: internal links, `hreflang` tags today, later the language switcher, banner and redirect.
- Code reads links from it, so a missing language or an unknown page is a type error.
- Markdown reads links from it through route keys (`route:privacy`), resolved at build time for the file's language; an unknown key fails the build.
- The Markdown plugin is loaded with the Astro config, so the dev server restarts automatically when the route map or the locale list changes.

### Translations

- One JSON dictionary per language; English is the source of truth.
- Dictionaries are typed from English, so a missing key or a missing dictionary is a type error.
- No i18n library: the site is static and renders at build time. Switch to Paraglide if we need plurals, ICU formatting or a translation platform.

### Pages

- **Landing**: one component, rendered by one wrapper per language.
- **Legal pages**: same pattern as the landing. One shared component per legal page picks the Markdown file of the current language and renders it in a shared legal layout.
  - One Markdown file per language, imported directly (no content collection): with a handful of pages, a typed per-language map is enough, and a missing language is a type error.
  - The last update date is written by hand in each Markdown file: it marks a deliberate change to the text, not any commit.
- **404**: one per language. nginx serves the French one for missing `/fr/` URLs.

### Meta

- Pages provide their title and their route key. Everything else (description, OG tags, `hreflang`) is derived in one shared head component.
- `hreflang` links come from the page's route map entry, plus `x-default`, which points to the default language. Pages without translations (404) pass no route key and get no links.
- The shared head appends the site name to the document title (`Legal notice | ReadRoll`). Pages whose title already contains it (landing) opt out.
- `og:title` stays without the site name, since `og:site_name` already carries it.
- The description and OG image depend on the language, not the page.
- No canonical and no `og:locale` for now.

## Language preference

- **First visit**: if the browser's first supported language differs from the page's, a dismissible banner suggests the matching page, written in the suggested language.
- **Every choice is saved before navigating**: switcher (target language), banner link (suggested language), banner dismiss (current language). Saving after navigating would cause a redirect loop.
- **Later visits**: a blocking inline script at the top of `<head>` redirects with `location.replace` to the stored language's page, before anything is painted. It is skipped on 404 pages.
- **Accepted trade-off**: a visitor with French stored who opens a shared English link lands on French. Crawlers have no storage, so they're unaffected.
- If a CSP header is added, the inline script's hash must be allowed.
